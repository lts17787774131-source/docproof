## 2. 三句话开场

1. **是什么**："一个能读财报的问答系统，答完能指给你看是第几页哪一格。"
2. **为什么做**："我以前做的文本问答在这种文档上只有 50 分，因为表格被拍平了，数字和表头对不上。"
3. **凭什么信**："我建了 300 道分层测试题，每一步优化单独做消融，每个数字都能复现。"

---

## 3. 90 秒 Demo 顺序（别改）

1. 上传一份真实年报 → 说"161 页，80 秒解析 + 索引完"
2. 问 2025 年营业收入 → **高亮表格** → 说"合并口径 5.86 亿，标的是第 71 页合并利润表"
3. 把「口径」切到"母公司" → 同一个问题变成 485886.24 → 说"两个都正确，看你要哪个口径；这是我给每张报表打的主体标签"
4. 问 2027 年数据 → 拒答 → 说"报告期是 2025，问未来年份它直接拒，不编"
5. 打开消融表 → 说"46.9 到 98.4，一步一个变量；真实口语集 87%，差距就是瓶颈所在"

## 4. 13 个追问（一句话版）

| 问题 | 一句话回答 |
|---|---|
| 创新点？ | DocIR + 结构切分 + 三档路由，三者都有消融数据支撑 |
| 和 RAGFlow/MinerU 区别？ | 他们解决"解析出来"，我解决"检索得到 + 引用得准" |
| 准确率怎么测？ | 300 题分层、LLM-judge + 30% 人工、McNemar 检验 |
| 提升来自哪？ | 指着消融表：B1 切分 +__pp，B2 表格 +__pp，B4 重排 +__pp |
| 为什么不用 CLIP？ | 密集小字检索弱，索引成本高；列为 V2 对照实验 |
| 表格为什么不用 Markdown？ | 丢坐标、丢合并单元格，没法高亮；Markdown 只是给 LLM 的视图 |
| 为什么不直接喂 VLM？ | 成本 8-15 倍、延迟不可接受；用帕累托曲线证明取舍 |
| 幻觉怎么控？ | 强制引用 + 蕴含校验 + 阈值拒答 + 拒答也给候选 |
| 500 页多久？ | 分页并行 + 增量索引；给压测数字 |
| 索引怎么设计？ | dense + sparse + 元数据，页级 hash 增量 |
| 成本多少？ | 给公式和量级；L3 占 20% 查询，贡献 __% 成本 |
| 最大坑？ | 讲跨页表格（E9 占 __%），怎么发现、怎么修 |
| 只有 8G 显存怎么跑？ | 开发期 Ollama 8B 全本地（8B+reranker 6.3G，embedding 走 CPU），终版切 DeepSeek；做了 provider 抽象、令牌桶、退避、成本计量 |

## 5. 反问面试官（3 个，显示你在想业务）

1. "你们现在文档类需求里，用户最不信任的是'答错'还是'答不出'？"（判断产品取舍）
2. "如果要做可审计，引用需要细到段落还是单元格？"（显示你想过落地）
3. "团队现在评测是怎么做的？有没有人工标注的闭环？"（显示你有方法论）

## 6. 五条红线

- ❌ 不说"我用 LangChain 搭了个 RAG"
- ❌ 不报没有来源的百分比
- ❌ 不说"调 prompt 就好了"
- ❌ 不把开源组件说成自研
- ❌ 不只讲技术不讲用户价值

## 7. HR 面的三个问题，提前想好

| 问题 | 答题结构 |
|---|---|
| 为什么做这个项目？ | 真实场景 → 具体痛点 → 现有方案为何失效 → 你的取舍（**必须有细节，别背稿**） |
| 这个项目能干嘛？ | 一句话价值 + 三个用户场景 + 一句"它不做什么" |
| 你最大的收获？ | 不是技术，是"先建评测再优化"的方法论 —— 这句话对 HR 和技术面都成立 |
