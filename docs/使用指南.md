# DocProof 使用指南

> 面向：想跑起来、想改、想拿去面试演示的人。
> 前提：Windows + PowerShell。Linux/macOS 把 `.\` 换成 `./`、`$env:X=` 换成 `export X=` 即可。

---

## 0. 30 秒理解它在干什么

```
PDF ──► 解析（文本/表格/图 + 坐标）──► DocIR ──► 结构切分 ──► 检索 ──► 生成 ──► 答案 + 引用
                                                                              │
                                                                    每条引用带页码和 bbox，
                                                                    前端点一下就能高亮原文
```

三个关键点：

1. **表格不被拍平**：每行自带列名（`第三季度：营业收入(亿元)=12.4`），所以能算、能比、能引用。
2. **报表打口径标签**：`合并利润表` / `母公司利润表` 分开存，问哪张表答哪张表。
3. **答不了就拒**：数字闸门 + 未来年份闸门，宁可拒答也不编。

## 1. 环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| 系统 | Windows 10/11 | 其他系统命令微调即可 |
| Python | **3.12**（别用 3.14） | 3.14 没有 pymupdf 的 wheel，会装不上 |
| Ollama | 0.3+ | 提供 `bge-m3`（向量）与 `qwen3:8b`（生成） |
| 显卡 | 8G 显存够用 | 峰值约 6.3G；没有独显也能跑（生成会慢） |

检查：

```powershell
ollama list        # 应能看到 bge-m3 和 qwen3:8b
D:\anaconda1\python.exe --version   # 或任意 3.12 解释器
```

没有模型就先拉：

```powershell
ollama pull bge-m3
ollama pull qwen3:8b
```

## 2. 五分钟跑起来

```powershell
# ① 建虚拟环境（用 3.12）
D:\anaconda1\python.exe -m venv .venv312
.\.venv312\Scripts\python.exe -m pip install -r requirements.txt

# ② 造一份合成语料（6 份年报 + 76 道题，不需要联网）
.\.venv312\Scripts\python.exe scripts\make_corpus.py

# ③ 建索引（解析 → 切分 → 向量，约 10 秒）
.\.venv312\Scripts\python.exe scripts\build_index.py --reset

# ④ 跑一次消融，确认能出数（约 10 秒）
.\.venv312\Scripts\python.exe src\docproof\eval\runner.py

# ⑤ 起服务
$env:PYTHONPATH="$PWD\src"
.\.venv312\Scripts\python.exe -m uvicorn docproof.api.app:app --host 127.0.0.1 --port 7860
```

打开 <http://127.0.0.1:7860>，应该看到 6 份文档。

**验收标准**：第 ④ 步的表格里 `B2` 行准确率是 **98.4%**。

## 3. Web 界面怎么用

### 3.1 上传

左下「上传 PDF」→ 选择文件 → 点「建索引」。完成后会显示 `页数 / 块数 / 耗时`。

> 161 页真实年报约 80 秒，277 页约 90 秒。**当前是同步建索引**，大文件请耐心等。

### 3.1.1 管理索引（删 / 重建）

文档列表每一行左侧有勾选框，顶部工具条四个按钮：

| 操作 | 行为 | 用在哪 |
|---|---|---|
| **重建所选** | 重新解析 PDF → 重新切分 → 重新向量化（覆盖旧索引） | 改了解析/切分逻辑后，不用重新上传 |
| **删除索引** | 只删块和向量，**文档记录保留**，列表里显示「未索引 · 可重建」 | 清掉脏索引，稍后还能重建 |
| **彻底移除** | 删索引 + 文档记录 + 页面图（**PDF 源文件保留**） | 清理测试文档 |
| 全选 | 勾上当前所有文档 | 批量清理 |

几个实现细节（被踩过才知道）：

- 「删除索引」刻意**不删文档记录**——记录里存着 `source_path`，删了就没法重建了。
- 重建走的是同一个 `_index_path()`，和上传完全一致的链路，不会出现"上传/重建两套逻辑"。
- 删除/重建都在后端同步执行；批量操作前端是**逐个串行**调用，避免把 8G 卡打满。

### 3.2 提问

选中左侧文档 → 输入问题 → 点「提问」。

| 控件 | 选项 | 什么时候用 |
|---|---|---|
| provider | `extractive` | 默认，离线、快、确定性强 |
| | `ollama` | 需要计算/归纳（如"增长了多少"），约 6 秒一题 |
| 口径 | `自动` | 问题里提到"母公司"就按母公司，否则合并 |
| | `合并报表` / `母公司报表` | 强制指定，用来现场对比 |

同一个问题切换口径，答案会变：

```
2025年营业收入是多少？   自动/合并 → 586499360.82（第 71 页 · 合并利润表）
2025年营业收入是多少？   母公司    → 485886.24   （第 73 页 · 母公司利润表）
```

### 3.3 看结果

- **回答区**：答案正文 + `route / 耗时 / 是否拒答`。超过 200 字会折叠成"…"，点「展开全文」看全部；「复制答案」把完整文本复制出来（PDF 文字不能选的时候特别有用）。
- **引用卡片**：`[E1] 第 71 页 · 合并利润表 · 核对通过`，点一下右侧显示原文并画红框；卡片上的「复制全文」复制**整块原文**（不只是答案那句）。
- **其他相关答案**：列出 top-5 召回块各自最相关的一句，每一条都能「定位原文」，也能「复制这段 / 复制整块」。问"名字""目录"这类题时，所有相关段落会一次摊开，不用一条条问。
- **检索证据**：top-5 的分数与来源，用来判断"是没检索到还是答错了"。
- **拒答**：显示黄色徽标与原因（`number_absent` / `future_year` / `low_coverage`）；**拒答时也会列出最接近的候选**，而不是一片空白。

### 3.4 目录页 / 论文类文档

论文的目录页每一行都像"标题"，早期版本会把它们全部当标题丢掉，导致问"目录"只能返回摘要页。现在：

- 连续 2 个以上的标题会合并成**一个目录块**（带 `toc` 标记）入索引；
- 问"目录 / 目次 / contents"时，直接返回**整块目录**，而不是其中一行；
- 同义词会自动扩展（中文问"目录"、英文页写 Contents 也能命中）；
- **导航词加权**：目录/摘要/参考文献/结论出现在段首时强加权，避免"论文的目录"被正文里提到"论文"的段落抢答；
- **点线条目排除**：目录里的"参考文献……67"也是以关键词开头，用点线占比把它和真正的参考文献章节区分开。

实测（73 页论文）：`目录`→第 6 页、`论文的目录`→第 6 页、`摘要`→第 4 页、`参考文献`→第 67 页、`结论`→第 65 页。

## 4. 用自己的 PDF

```powershell
# 放到 data\raw\ 或任意目录，然后指定 --raw
.\.venv312\Scripts\python.exe scripts\build_index.py --raw "D:\我的文档" 

# 单题验证（不传 --doc-id 时默认取最新一份）
.\.venv312\Scripts\python.exe scripts\ask.py "2025年营业收入是多少？" --doc-id <doc_id>
```

`doc_id` 在 `python scripts/build_index.py` 的输出里，或直接看网页左侧列表。

**扫描件**（没有文本层）：当前只做文本层抽取，扫描页会被记进 `scanned_pages`，需要 OCR 才能答。

## 5. 命令行速查

| 命令 | 作用 | 常用参数 |
|---|---|---|
| `scripts/make_corpus.py` | 造合成语料 + 金标题 | 无 |
| `scripts/build_index.py` | 解析 + 切分 + 入库 + 向量 | `--raw` 目录、`--reset` 清库重建、`--mode fixed` 用定长基线、`--no-dense` 只建 BM25 |
| `scripts/ask.py` | 单题问答 | `--doc-id`、`--provider extractive\|ollama\|deepseek`、`--json`、`--no-dense` |
| `scripts/inspect_doc.py` | 打印一份 PDF 的解析结果 | 位置参数：PDF 路径 |
| `scripts/eval_real.py` | 跑真实口语 15 题 | 无 |
| `scripts/fetch_real_reports.py` | 从巨潮拉真实年报 | `--n 2`、`--max-pages 40` |
| `src/docproof/eval/runner.py` | 跑合成集消融（B0–B4） | 无 |

示例：

```powershell
# 看解析质量：表格识别对不对、章节切得对不对
.\.venv312\Scripts\python.exe scripts\inspect_doc.py "data\raw\华信科技2023年年度报告.pdf"

# 单题输出完整 JSON（含 top-5 证据、bbox）
.\.venv312\Scripts\python.exe scripts\ask.py "哪个季度营收最高？" --doc-id <id> --json

# 拉 3 份真实年报到 data\raw_real（前 40 页）
.\.venv312\Scripts\python.exe scripts\fetch_real_reports.py --n 3 --max-pages 40
```

## 6. 评测怎么跑、结果在哪

两套数据集，回答两个不同的问题：

| 数据集 | 文件 | 回答什么 | 命令 |
|---|---|---|---|
| 合成集（76 题） | `eval/datasets/gold.jsonl` | **每个模块贡献多少**（消融） | `runner.py` |
| 真实口语集（15 题） | `eval/datasets/real_qa.jsonl` | **真实提问到底行不行** | `eval_real.py` |

产物：

```
eval/reports/ablation.md          # 人读的消融表（含置信区间、McNemar）
eval/reports/ablation.json        # 机器读
eval/reports/predictions_B*.jsonl # 每题：预测、引用、top-1、耗时
eval/reports/real_reports.json    # 真实年报解析统计
```

预期结果：

| 集合 | 结果 |
|---|---|
| 合成集 B0 → B2 | 46.9% → 98.4%（+51.6pp，33 胜 0 负） |
| 真实口语集 | 13/15 = 87% |

> 两个数字差 11 个点，不是 bug，是**合成题模板化**的必然结果——报告第 7 节写了原因。

## 7. 配置

### 7.1 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `OLLAMA_URL` | `http://127.0.0.1:11434` | Ollama 地址 |
| `DOCPROOF_EMBED_MODEL` | `bge-m3` | 向量模型 |
| `DOCPROOF_LLM_MODEL` | `qwen3:8b` | 生成模型 |
| `DEEPSEEK_API_KEY` | 空 | 填了才能用 `--provider deepseek` |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | 兼容 OpenAI 协议 |
| `DEEPSEEK_MODEL` | `deepseek-chat` | 终版数字用它复跑 |

### 7.2 代码里的关键参数（`src/docproof/config.py`）

| 参数 | 默认 | 改了会怎样 |
|---|---|---|
| `child_size` | 240 | 子块大小，越小检索越准、上下文越碎 |
| `top_k` | 8 | 送进生成的证据数 |
| `recall_k` | 5 | 评测用的 Recall@k |
| `fixed_size` | 512 | B0 基线的切分长度 |
| `page_dpi` | 150 | 页面图分辨率（前端高亮用） |
| `max_pages` | 0 | >0 时只解析前 N 页（大文档冒烟） |

## 8. 常见问题

**Q1：`pip install` 报 `No matching distribution found for pymupdf`**
用了 Python 3.14。换 3.12 重建 venv（本仓库用 `.venv312`）。

**Q2：`Connection refused` / 建索引卡住**
Ollama 没起。先 `ollama serve`（Windows 装完一般在托盘），再 `ollama list` 确认模型在。

**Q3：显存爆了 / 生成很慢**
8G 卡同时放 `qwen3:8b` + `bge-m3` 会超。当前设计是**分阶段加载**：建索引时用 embedding，
提问时用 LLM。别在同一个进程里同时热加载两者。

**Q4：上传后提问说"文档未索引"**
上传是同步的，等页面显示"完成"再问；或直接看 `[index]` 日志。

**Q5：端口 7860 被占用**
`--port 7861` 换一个；或先杀掉旧进程：`Get-NetTCPConnection -LocalPort 7860 | Select-Object OwningProcess`。

**Q6：PDF 是扫描件，答不出来**
当前不做 OCR。`inspect_doc.py` 会显示 `scanned=[...]`，这些页需要先 OCR 成文本层。

**Q7：表格答错 / 列名是"列5、列6"**
说明这页的表头没解析好（常见于跨页表：表头在上一页）。已知限制，见报告第 7 节。

**Q8：上传报 500 / 很慢**
旧版本有个 bug：向量缓存用的是 SQLite 连接，FastAPI 换线程处理第二个请求时会抛
`SQLite objects created in a thread can only be used in that same thread`。
已修（`check_same_thread=False` + 锁）。现在 1 页 PDF 上传约 **0.3–1 秒**。
若你的部署仍报这个错，升级到当前代码并重启服务即可。

**Q9：简历 / 信息表能问吗**
可以。表单类 PDF 的每个字段常是独立文本块，已按"字段：值"逐行切开，所以"手机号是多少"
能直接答出 `手 机：138****0000`。简历里"自我评价"这种章节标题也会自动接上正文。

**Q10：想从头再来**
```powershell
Remove-Item -Recurse -Force data\docproof.db, data\pages, data\parsed, data\embed_cache.db
.\.venv312\Scripts\python.exe scripts\build_index.py --reset
```

## 10. 代码结构（想改的时候看这里）

```
src/docproof/
  ingest/     解析：pdf_text.py（文本/标题）、tables.py（表格+合并单元格）、pipeline.py（编排+口径标签）
  ir.py       DocIR 定义 + 行式序列化（rows_text）
  chunking/   结构切分、定长基线、续表合并
  index/      bm25.py、dense.py（Ollama 向量）、store.py（SQLite）
  retrieve/   混合检索 + RRF + 同义词扩展
  generate/   providers.py（三种 provider + 表格算子）、answer.py（拒答 + 引用校验）
  eval/       metrics.py、runner.py
  api/        FastAPI + 单页前端
```

**改一个地方要重跑什么**：

| 改动 | 要重跑 |
|---|---|
| 解析/切分/表格 | `build_index.py --reset` |
| 检索/打分/provider | 不用重建，重启服务即可 |
| 评测指标 | `runner.py` / `eval_real.py` |

## 11. 已知边界（别踩）

1. 合成集 98.4% 是**上限**，真实口语 87%，别拿前者当真。
2. 扫描件不支持（无 OCR）。
3. 跨页表头会丢（部分列名显示为"列5"）。
4. 图表题答的是图注，不是真读图（VLM 未接）。
5. 建索引是同步的，大文件会阻塞上传。
6. 评测集小（76 + 15），置信区间宽，只适合看趋势。

更详细的分析见 [v0.1 评测报告](eval-report-v0.1.md)，方案与取舍见 [开发计划](00-开发计划.md)。
