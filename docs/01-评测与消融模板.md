# 评测与消融模板（可直接落盘使用）

> 配套 `00-开发计划.md` 第 8 章。目标：让"准确率从 52% 到 79%"这句话**可复现、可追问、可辩护**。
> 用法：把本文件的表格复制进 `eval/` 与 `docs/`，按顺序填。

---

## 1. 评测集格式（`eval/datasets/gold.jsonl`）

每行一条 JSON，字段如下（示例为**格式示意**，非真实数据）：

| 字段 | 必填 | 说明 |
|---|---|---|
| `qid` | ✓ | 全局唯一，如 `S1-FY2023-042` |
| `doc_id` | ✓ | 对应 PDF |
| `subset` | ✓ | S1 财报 / S2 政务 / S3 英文 / S4 不可回答 |
| `qtype` | ✓ | T1 单块事实 / T2 表格数值 / T3 表格推理 / T4 图表 / T5 跨页多跳 / T6 不可回答 |
| `question` | ✓ | 用户原话，**不要改写成书面语**（要保留真实口语） |
| `answer` | ✓ | 最小充分答案（数值带单位与口径） |
| `answer_type` | ✓ | number / entity / text / comparison / boolean / unanswerable |
| `gold_evidence` | ✓ | 数组，每项 `{page, block_id, note}`；T6 填 `[]` |
| `tolerance` | 数值题 | 如 `0.5%` 或 `±0.1` |
| `hard_negative` | 可选 | 容易混淆的块（测区分度） |
| `source` | ✓ | human / model-draft-human-verified |
| `notes` | 可选 | 出题人备注 |

**一条完整示例（示意）**：

```
{"qid":"S1-FY2023-042","doc_id":"annual_600xxx_2023","subset":"S1","qtype":"T2",
 "question":"第三季度营业收入同比多少？","answer":"+12.4%（单季，营业收入）",
 "answer_type":"number","gold_evidence":[{"page":42,"block_id":"p42_t3","note":"表3-2 本报告期列"}],
 "tolerance":"0.5%","source":"human"}
```

**硬性规则**：

1. 每题**必须**标到 block 级证据；标不出证据的题直接删掉（否则无法算 Recall）。
2. T6 题的 `answer` 统一写 `"NOT_IN_DOC"`。
3. 同一份文档的题不超过 25 道，防止单文档过拟合。
4. 出题时**不看系统输出**，避免"照着答案出题"。

## 2. 出题 SOP（12-15 小时完成 300 题）

| 步骤 | 动作 | 耗时 |
|---|---|---|
| 1 | 选文档，按 6 类题型分配配额（每类 ≥ 30） | 1h |
| 2 | 强模型自动出题（给页面文本 + 图，要求"必须看表格/图才能答"） | 2h |
| 3 | 人工筛：删掉"常识可答""答案含糊""证据不唯一"的题 | 5h |
| 4 | 补 T6 不可回答题（问不存在年份/不存在的指标） | 2h |
| 5 | 标 gold_evidence（用 M2 的 bbox 可视化工具点选） | 4h |
| 6 | 盲测复核：隔一天再检查 20%，看答案是否唯一 | 1h |

**质量红线**：随机抽 30 题让同事答，若他能答对 < 60%，说明题目太难或证据不清，需返工。

## 3. 指标定义（写进报告首页，防止口径漂移）

```
Answer Acc = 正确题数 / 可回答题数（T1-T5）
  · 数值题：|预测 - 标准| <= tolerance 且 单位/口径一致
  · 文本题：关键实体全中 且 无矛盾陈述
  · 判定：rubric LLM-judge；30% 抽样人工复核；分歧以人工为准

Recall@k = 命中题数 / 总题数
  · 命中 = gold_evidence 中任一 block 出现在 top-k

Citation Precision = 正确引用数 / 引用总数
  · 正确 = 引用块文本蕴含该句结论（规则 + LLM judge）

Citation Recall = 有引用的关键结论数 / 关键结论总数

Refusal Acc = T6 正确拒答数 / T6 总数
False Refusal = T1-T5 中被拒数 / T1-T5 总数

p95 Latency：首字延迟 与 完整答案延迟 分开报，单位 ms
Cost：每 100 次问答的 token 费用（按当日单价换算，报告里写单价）
```

## 5. 错误标注表（`eval/reports/errors.csv`）

对**每一个错题**标一个主错误码（可加次错误码）：

| 错误码 | 判据（怎么判定它是这一类） |
|---|---|
| E1 解析丢失 | 打开页图，肉眼看不到该表格/文字，或 OCR 明显错字 |
| E2 切分切断 | 证据跨块，且没有任何单块含完整答案 |
| E3 表头错配 | 数值正确但列含义错（如"同比"当成"环比"） |
| E4 检索未召回 | 金标块不在 top-20 |
| E5 排序挤出 | 在 top-20 但不在 top-5 |
| E6 生成读错 | 证据齐全且正确，模型算错/读错 |
| E7 引用错位 | 答案对，但引用块不含该结论 |
| E8 拒答错误 | 该拒未拒 / 不该拒而拒 |
| E9 跨页未合并 | 续表被当两表，证据被拆散 |
| E10 单位口径 | 万元/元、单季/累计、同比/环比混淆 |

**产出**：每轮迭代一张堆叠柱状图（E1-E10 占比）。

**判读方法**（这段直接写进报告，是"会分析"的证据）：

- E4+E5 占比高 → 问题在检索，优先调切分/混合/重排
- E1+E2 占比高 → 问题在解析，别再去调 prompt
- E6 占比高 → 才轮到换模型或改 prompt
- E3+E10 占比高 → 是领域知识问题，考虑加"口径校验"规则

## 6. 统计检验模板（报告里照抄这段结构）

```
样本：n = 300（T1-T5 = 250，T6 = 50）
对比：B0 vs B6，配对二分类
方法：McNemar 检验（连续性校正）
结果：B0 正确 130/250（52.0%），B6 正确 198/250（79.2%）
      discordant pairs: b=85（B0错B6对）, c=17（B0对B6错）
      χ² = 43.6, p < 0.001
效应量：+27.2pp，95% CI [21.0, 33.4]（bootstrap 1000 次）
```

> 只要报告里出现这一段，面试官对你的信任度会立刻上一个台阶。

## 7. 评测报告骨架（`docs/eval-report.md`）

```
1. 摘要（5 行：做了什么、基线多少、现在多少、代价多少、最大局限）
2. 数据集（来源、规模、分层、标注方式、已知偏差）
3. 指标定义（照抄第 3 节）
4. 主结果表（B0 vs B6，分题型）
5. 消融（第 4 节的表 + 柱状图）
6. 参数扫描（4 张小图）
7. 错误分析（堆叠图 + 3 个典型案例的截图）
8. 成本与延迟（帕累托图 + 瀑布图）
9. 局限性（诚实写：图表类最弱、扫描件质量依赖、跨文档不支持）
10. 复现方式（命令、版本、seed）
```

**第 9 节一定要写**。一份只讲优点的评测报告，在资深面试官眼里等于没做完。

## 8. 每次实验必须落盘的 5 个文件

| 文件 | 内容 | 为什么 |
|---|---|---|
| `predictions.jsonl` | 每题：答案、引用、top-k 块、耗时、token | 复查与错误归因的唯一依据 |
| `run_meta.json` | git commit、模型版本、prompt 版本、参数、seed | 可复现 |
| `metrics.json` | 全部指标的机器可读结果 | 画图与对比 |
| `errors.csv` | 错误码标注 | 错误分析 |
| `report.md` | 人读的结论 | 直接进 docs/ |

> 缺任何一个，这个数字在面试时就"不可信"。
