## ① PDF 文本层与坐标系（PyMuPDF）

**概念**：PDF 有两种页——"文字页"（每个字符带坐标，能选中复制）和"图片页"（整页是一张图，只能 OCR）。**文本层**就是文字页里那份"字符 + 坐标"的清单。

**打比方**：PDF 像一张设计稿，文本层是设计稿的"图层信息"；扫描件是拍下来的照片，没有图层。

**本项目示例**：

```python
page.get_text("dict")        # 拿到 blocks → lines → spans，每个 span 有 bbox 和字号
# 一个 block 的 bbox（单位 pt，A4 是 595×842）：(76.9, 259.4, 516.2, 279.4)
```

存进 DocIR 时**归一化成 0-1**：`x0/width, y0/height, ...` → `(0.129, 0.308, 0.867, 0.427)`。
好处：换分辨率（150dpi 页面图 vs 原始 PDF）不用重算，前端直接用百分比定位。

**追问**："怎么判断是扫描件？"
→ 一页抽出来的字符数少于 40 且没识别到表格，就记进 `scanned_pages`。真实年报 80% 有文本层，所以 OCR 只处理扫描件。

## ② 版面分析（用启发式，不用深度学习）

**概念**：把一页切成"标题 / 正文 / 表格 / 图 / 页眉页脚"几类块。工业界常用 DocLayout-YOLO 这类模型；本项目用的是**字号 + 位置 + 正则**的规则。

**打比方**：模型是"看图猜结构"，规则是"看排版习惯猜结构"——年报的标题一定比正文大、一定在段首。

**本项目示例**（三条规则，按优先级）：

```python
is_footer  = 紧贴页边 且 文本短            → 页眉页脚
is_heading = 字号 ≥ 正文×1.12 且 短 且 不含句读 → 标题
is_heading |= 匹配「第X节 / 一、 / 1.1」     → 标题
```

**踩过的坑（面试讲这个很加分）**：一开始按**每页**统计正文字号，结果表格多的页面里 9pt 的表格文字把"正文基准"拉到 8.5pt，10.5pt 的正文全被判成标题。
**修法**：字号统计**排除表格区域**，并且改为**全文档一个基准**。

**追问**："为什么不用 DocLayout-YOLO？"
→ ① 目标文档 80% 有文本层，规则够用；② 8G 卡上少一个 2G 的模型；③ **规则可解释**——被问"这块为什么判成标题"能答上来。

## ③ 表格识别（含合并单元格）

**概念**：从页面上找出表格区域，再把"线框"还原成"行 × 列 + 每个单元格的坐标"。

**打比方**：相当于把一张 Excel 截图，反推回 Excel。

**本项目做法**：`page.find_tables()` 找到表，拿到 `rows[r].cells[c]`（每个格子的矩形），然后：

1. **逐格取字**：`page.get_text("clip=单元格矩形")`。
   > 坑：直接用 `table.extract()` 在部分 PDF 上会把字符顺序打乱（`10.2` 变成 `10 2\n.`），所以改成按矩形取。
2. **还原合并**：同一个矩形在相邻列/行重复出现 → 说明是合并单元格，算出 `colspan/rowspan`。
3. **表头映射**：合并表头的矩形可能和数据列**错位一格**，所以按 **x 坐标重叠**把表头名映射到列，而不是按列序号。

**示例**（真实年报第 8 页）：

```
列名：2025 年 | 2024 年 | 本年比上年增 | 2023 年
营业收入：2025 年=586499360.82；2024 年=567976026.12；本年比上年增=3.26%
```

对比没有这一步时，同一个表会被序列化成 `列名： | 项目 |  |`（列名全空），下游全废。

**追问**："合并单元格怎么识别？"
→ 单元格矩形**相等**就说明是同一块（PyMuPDF 会把同一个 Rect 重复给合并区域里的每个格子），再数它横跨几列/几行。

## ④ DocIR（文档中间表示）

**概念**：解析完不直接进检索，而是先转成一套**统一的块结构**，后面所有模块只认它。

**打比方**：像编译器里的 IR（中间表示）——前端（各种 PDF）→ IR → 后端（检索/生成），换解析器不影响下游。

**本项目字段**（只保留三类用途需要的）：

| 字段 | 用途 |
|---|---|
| `page`、`bbox`、`block_id` | **引用**：能指回第几页哪个位置 |
| `type`、`section`、`text` | **检索**：标题/正文/表格/图，带章节路径 |
| `html`、`cells`、`header`、`rows` | **展示与计算**：表格结构和单元格坐标 |

**示例**（一个块的真实样子）：

```json
{"id":"doc:t3_0","page":8,"type":"table","bbox":[0.13,0.31,0.87,0.43],
 "section":"第三节 会计数据和财务指标",
 "header":["营业收入","2025 年","2024 年"],
 "rows":[["营业收入","586499360.82","567976026.12"]]}
```

**追问**："为什么 bbox 要归一化？"
→ 页面图可能是 150dpi 也可能是 200dpi，坐标除以页宽页高之后，前端用百分比就能定位，换分辨率不用重算。

## ⑤ 切分（Chunking）：定长 vs 结构 vs 父子块

**概念**：检索的单位不是"整篇文档"，而是"块"。块怎么切，直接决定能不能检索到。

**打比方**：把一本书拆成卡片。按字数硬切（定长）会把一句话、一张表切成两半；按章节切（结构）能保证一张卡片讲完一件事。

**三种策略对比**：

| 策略 | 做法 | 问题 |
|---|---|---|
| 定长（基线 B0） | 每 512 字切一刀 | 表格被切散、标题被切走 |
| 结构（B1） | 标题并入下文、表格整表、图=图注+邻文、跨页续表合并 | 规则多，边界情况多 |
| 父子块（small-to-big） | 子块 240 字用于**检索**，父块 1600 字用于**生成** | 存储翻倍 |

**为什么父子块有效**：检索要"准"（块小、噪声少），生成要"全"（上下文够）。两者矛盾，就存两份。

**跨页续表**：财报的现金流表常跨两页。检测信号是"（续上页）表 3" + 表头相同，然后把第二页的行并回第一张表。

**追问**："为什么不用固定长度？"
→ 表格被切断就是**永久丢信息**：`第三季度` 在第一块、`12.4` 在第二块，两块单独看都不完整。我的消融里定长 46.9%、结构切分 56.2%。

## ⑥ 分词与 BM25（稀疏检索）

**概念**：BM25 是"按词匹配 + 加权"的经典检索算法。三个直觉：
1. 词越少见越重要（IDF）；
2. 一个词在文档里出现越多越相关，但**边际递减**（TF 饱和）；
3. 长文档要打折（长度归一化）。

**公式**：

```
score(q,d) = Σ  IDF(t) · [ tf · (k1+1) ] / [ tf + k1 · (1 - b + b · |d|/avgdl) ]
IDF(t) = ln(1 + (N - df + 0.5) / (df + 0.5))
```

`k1=1.5`（词频饱和速度）、`b=0.75`（长度惩罚强度），这是项目里的取值。

**手算一个例子**（假设 100 篇文档）：

- 查询"第三季度 营业收入"，某文档含"第三季度" 1 次、"营业收入" 3 次
- "第三季度"只在 3 篇里出现 → IDF = ln(1 + 97.5/3.5) ≈ 3.3（很稀有，权重高）
- 若文档长度是平均长度的 1.2 倍 → 分母里的长度惩罚 ≈ 1.1
- 两项加起来就是这篇文档的分数

**本项目示例**：中文要先分词（jieba），但"12.4""2025"这类数字单独进倒排——财报问题的检索信号主要来自数字和年份。

```python
tokenize("第三季度营业收入 12.4 亿元")
# → ['第三季度', '营业收入', '12.4', '亿元', '12.4']
```

**追问**："中文分词有什么坑？"
→ ① 财报术语要加自定义词典（"扣非净利润"不能被切碎）；② PDF 里常有排版空格把词拆开（"手  机" → 手 / 机），要先去掉**中日韩字符之间**的空格；③ 数字要单独处理，否则"第三季度"和"3 季度"匹配不上。

## ⑦ 向量检索（稠密检索）

**概念**：把文本映射成一个高维向量（本项目的 bge-m3 是 1024 维），语义相近的向量在空间里也相近，用**余弦相似度**衡量。

**打比方**：BM25 是"对字面"，向量是"对意思"。"营收"和"营业收入"字面不同、向量很近。

**公式**：

```
cos(a, b) = (a · b) / (|a| · |b|)
```

**示例**：`[1,0]` 和 `[0.8,0.6]` → `0.8 / (1×1) = 0.8`；正交（`[1,0]` vs `[0,1]`）→ 0。

**本项目**：`ollama` 提供 `bge-m3`，1024 维，写入时归一化（这样点积就等于余弦），存进 SQLite 的 BLOB。查询时算一次矩阵乘法就得到全库相似度。

**追问**："向量检索一定更好吗？"（这题我实测翻过车）
→ 不一定。**数字型问题上 BM25 更强**：问"第三季度营收"，向量会把语义相近的"全年营收"也召回来，而 BM25 靠精确词元更准。我的消融里加向量后准确率**没涨**（98.4% → 98.4%，MRR 反而从 0.73 降到 0.65）。

## ⑧ RRF 融合（混合检索）

**概念**：BM25 和向量各给一个排名，把两个排名**融合**成一个。RRF 只看名次、不看分数，所以不用调权重。

**公式**：

```
score(d) = Σ_r  1 / (k + rank_r(d))        k 通常取 60
```

**手算例子**（k=60）：

| 文档 | BM25 排名 | 向量排名 | RRF 分数 |
|---|---|---|---|
| A | 1 | 3 | 1/61 + 1/63 = 0.0323 |
| B | 2 | 1 | 1/62 + 1/61 = 0.0325 |

→ B 略胜。注意 A 在 BM25 里更好，但 B 在两个榜单里都靠前，融合后反超。

**为什么用 RRF 而不是加权求和**：BM25 分数是 0~30，余弦是 -1~1，量纲不同，加权要先归一化；RRF 只用名次，天然免疫。

**追问**："k 取 60 是什么作用？"
→ 控制"头部差距"。k 越小，第一名越占绝对优势；k 越大，各名次越平均。

## ⑨ 重排（Reranker）

**概念**：先用便宜的方法召回 20 条，再用贵的模型逐条精排到 5 条。

**打比方**：海选（召回）→ 复试（重排）。海选看谁不淘汰，复试看谁最合适。

**本项目**：实现了 `bge-reranker` 的接口位，但**没启用**——因为 8G 卡上和 8B 生成模型抢显存，而且消融里向量路本身没增益，先重排收益不明。

**追问**："为什么没上重排？"
→ 诚实答：这是排在 MVP-2 的事；先做能证明有效的（结构切分），而不是堆模块。如果上，会先做**小模型 + 只对表格块**。

---

## ⑩ 生成（RAG 的 G 部分）

**概念**：把检索到的证据拼进 prompt，让模型"只根据证据回答"。

**打比方**：开卷考试。检索是翻书，生成是抄答案，引用是标注页码。

**本项目三种 Provider**：

| Provider | 用途 | 特点 |
|---|---|---|
| `extractive` | 消融实验 | 确定性：从证据里挑最相关的句子。**不受模型随机性影响**，所以消融的差异只来自检索 |
| `ollama` (`qwen3:8b`) | 交互演示 | 本地、免费、约 6 秒/题 |
| `deepseek` | 终版数字 | 云端、快、中文强 |

**Prompt 的关键约束**（节选）：

```
只能依据给定证据回答；证据不足必须拒答；
输出 JSON：{"answer": "...", "citations": ["E1"], "refuse": false}
答案里的数字必须与证据完全一致，禁止换算或推断
```

**追问**："为什么消融用 extractive 而不是大模型？"
→ **控制变量**。大模型有随机性，同一题两次可能不同；抽取式是确定性的，B0→B2 的差异才能归因到切分/检索，而不是"模型今天心情好"。

## ⑪ 拒答与引用校验

**概念**：RAG 最危险的不是答不出，是**编得像**。所以要两道闸：答不了就拒、答了必须能对上原文。

**打比方**：会计做账要有凭证；没有凭证的数字不许入账。

**本项目的四道闸**：

| 闸门 | 规则 | 例子 |
|---|---|---|
| 数字闸门 | 问题里的年份/金额在证据里完全找不到 → 拒 | 问"2027 年营收"，文档只到 2025 |
| 未来年份 | 报告期 2025，问 2026 → 直接拒 | 即使正文提到"2026 年计划"也不答 |
| 覆盖度 | 问题实词在证据里覆盖 < 50% → 拒 | 问"董事长姓名"，文档全是财务数据 |
| 引用校验 | 答案里的数字必须出现在它引用的块里 | "增长 3.2 亿"，3.2 不在原文 → 校验失败 |

**计算型答案的特殊处理**：`12.4 - 8.1 = 4.3`，4.3 本来就不在原文。所以校验的不是结果，而是**依据的两个数**是否都在引用块中。

**效果**：误拒率 2%，不可回答题拒答率 100%。

**追问**："拒答太多会不会影响体验？"
→ 会，所以拒答时**仍然返回最接近的 3 个候选区域**，让人自己判断；误拒率是当护栏指标在看（从 19% 降到 2%）。

## ⑫ 评测指标

**概念**：没有指标的优化都是玄学。检索和生成要分开量。

| 指标 | 公式 / 含义 | 本项目 |
|---|---|---|
| Recall@k | 金标证据是否出现在前 k 条 | R@5 = 77% |
| MRR | 第一条正确结果的排名倒数均值 | 0.73 |
| Answer Acc | 答案对不对（数值题要求数字全中） | 46.9% → 98.4% |
| Citation P | 引用的块是否真的包含证据 | 76% |
| 误拒率 | 能答的题被拒的比例 | 2% |

**置信区间**：76 道题只有 64 道可答，分数本身有波动。用 **bootstrap**（有放回重采样 1000 次）估区间：`+51.6pp，95% CI [39.1, 64.1]`。

**显著性检验**：同一批题、前后两次，用 **McNemar 配对检验**——只看"变了的那部分"（基线错→新对 = b，基线对→新错 = c）。本项目 `b=33, c=0, p<1e-4`。

**追问**："64 道题也敢下结论？"
→ 不敢下强结论，所以报了置信区间（±12pp），并且用**配对检验**（同一批题，个体差异被消掉）。真要下结论得 300 题——这是我写在报告局限里的第一条。

## ⑬ 消融实验（Ablation）

**概念**：每次只改一个变量，看分数变化，从而知道"哪一步真正有用"。

**打比方**：做菜加调料，一次只加一样，才知道是盐还是糖起了作用。

**本项目的阶梯**：

| 组 | 只改了什么 | 准确率 |
|---|---|---|
| B0 | 定长切分（基线） | 46.9% |
| B1 | 结构切分 | 56.2% |
| B2 | 表头随行 + 表格算子 | **98.4%** |
| B3 | 加向量检索 | 98.4%（MRR 反降） |

**关键结论**：**两步吃掉全部增益**，再叠模块只增加延迟。这比"我用了 8 个技术"更有说服力。

**追问**："B1 为什么只涨 9 个点，B2 却涨 42 个点？"
→ B1 解决的是"图能不能被检索到"（图表题 0→100%），但表格只是从"被切散"变成"整块"，列名还是靠猜；B2 把每行变成"自带列名的事实句"，比较/跨页/计算三类题才**拿得到输入**。

## ⑭ 服务化（FastAPI + SQLite + Provider）

**概念**：把上面那条链路包成 HTTP 接口，前端能调。

**打比方**：算法是菜谱，服务是餐厅——要能点单、上菜、处理投诉。

**技术选型与理由**：

| 选型 | 为什么 | 代价 |
|---|---|---|
| FastAPI | 异步原生、自带文档（/docs）、Pydantic 校验 | 同步函数跑在线程池，注意线程安全 |
| SQLite | 单机零运维，一张库装下文档/块/向量 | 并发写弱，规模大了要换 pgvector |
| Provider 抽象 | 本地 8B / 云端 API 一行配置切换 | 多一层抽象 |

**踩过的坑**：向量缓存用了 SQLite 连接，FastAPI 换线程处理第二个请求就抛
`SQLite objects created in a thread can only be used in that same thread`。
修法：`check_same_thread=False` + 一把锁。

**追问**："为什么不用 pgvector？"
→ 单机 MVP，SQLite 够用且零运维；表结构（metadata + 向量）是照着 pgvector 设计的，换的时候只改 DAO。

---

## ⑮ 前端高亮（bbox → CSS）

**概念**：后端返回归一化坐标，前端把它变成 CSS 的百分比定位，盖在页面图上。

```js
// bbox = [0.129, 0.308, 0.867, 0.427]
box.style.left   = (x0 * 100) + '%';
box.style.top    = (y0 * 100) + '%';
box.style.width  = ((x1 - x0) * 100) + '%';
box.style.height = ((y1 - y0) * 100) + '%';
```

**为什么用百分比**：图片宽度随窗口变，百分比跟着变，坐标不用重算。

| 技术 | 一句话 | 本项目数字 |

## 三个"讲出来最加分"的坑

1. **表内字号污染正文字号** → 10.5pt 正文被判成标题，段落被拦腰截断。修法：字号统计排除表格区 + 全文档基准。
2. **`table.extract()` 字符乱序** → `10.2` 变成 `10 2\n.`。修法：按单元格矩形 `get_text(clip=)`。
3. **指标不动** → Recall@5 四组完全相同，查下来是"定长切分只切出 2 个块，top-5 覆盖全语料"。修法：加长语料 + 中文改字符 bigram + 加 R@3/MRR。

> 这三个的共同点：**不是模型问题，是解析和评测问题**。面试时讲这个，比讲"我用了什么模型"值钱得多。
